# IntelWarden collection coverage

Maintained with v1.1.4 Preview 3. Baseline: RC1. This is a source and contract audit, not a claim of live verification. The pinned Forever API reference is build 1.60.1.70425, commit b401e0332adfbf0460d319b06d8ea29279a941f1. Native behavior of new collectors remains pending.

## Gates and storage

Every collector requires Olympus authorization, a supported current character, world entry and the existing recording consent (5). Optional module gates apply independently. Expanded witnessed Intel also requires the new, separate open-world Intel opt-in (1); it defaults off. Duel consent (1) remains separate. No setting silently grants another consent.

One source event is retained in the existing schema-6 ledger, with GUID references in derived dossiers. Native immutable captures remain content addressed. New observations use the same startup journal (2), including reload recovery, validation failure preservation and logout freezing. No new saved player database, saved aggregate statistics, expiry or history rewrite is introduced. Ordinary settings remain in OlympusChatWardenDB; the existing journal and Relay roots retain their identity.

All native input passes readable/secret checks before comparison, arithmetic or association. Unit identities are checked before and after reading. A readable GUID can support GUID-only outcome evidence; name-only data cannot associate a player. Loss of visibility means unknown current state. No collector enables nameplates or reads hidden players.

Status: **I** implemented with offline tests; native verification pending unless explicitly stated. **F** future candidate. **U** no supported reliable general path established. **X** deliberately excluded. API availability alone does not verify semantics.

## Deliberate limitations

Current watchlist status is used only after validated personal data becomes available. During unresolved startup context, important-only enrichment is restricted, rather than claiming complete rich capture or applying today's status retroactively. New live relationships can qualify immediately. Base deaths and credits are retained regardless of cached tier. The 512-entry runtime relationship cache and 600-entry sighting cache are disposable; capacity can restrict enrichment or cause another routine sighting, never delete source history. Native events delivered twice without a stable incident ID cannot always be proven duplicates. Distinct native death notices and alive/dead transitions therefore have separate counts; no invented combined death total or PvP K/D is presented.

## Required native acceptance

With consent on and off, test nameplate recycling, unreadable GUIDs, visible corpses, alive/dead/recovery, PvP flag changes, Important casts, ordinary filler casts, native PARTY_KILL/UNIT_DIED, same opponents dying twice, normal inspection, duels, roster/boss associations and BG objectives. Repeat during delayed validation, reload/merge, module switching and logout. Compare source evidence and owner attribution. Keep new native results separate from offline fixtures. No public release is authorized by this matrix.
